**Status:** candidate; evidence-only; no authority, deployment, or semantic-truth claim.  
**Canonical references:** `docs/ONTOLOGY.md`, `docs/CORPUS_MINDMAP.md`, `sovereign-omega-v2/src/core/types.ts` (`HolonMetadata`), `harness/sdk/meaning_heritage.py` (MHP-1 v1.3), `harness/sdk/heritage_composition.py`.  
**Research ancestor:** AEGIS Ω Meaning Heritage Protocol MHP-1 / ULC-1, 2026-08-21; source Drive document `1BsjFB_9_nmTp3_VzscrSuUO-yFGWVOFp`.

## Problem

A token or number is not a context-free meaning. The same bytes can originate in distinct artifacts, at distinct offsets, and be interpreted under different explicitly admitted contexts. `HolonMetadata` captures parent/child structure, tier, ontology name and research-document references; MHP-1 captures the semantics of verified derived claims, losses, additions and transitive ancestry. Neither type on its own connects **source occurrence** to **multiple competing verified-lineage readings**.

## Source-bound vertical slice

- `HolonSnapshotV1.from_typescript_record` parses exactly the nine `HolonMetadata` fields (lowercase scale values). Undeclared extra fields, self-edges, parent-child overlap and missing T0–T2 research references fail. `provenance` is **a declaration**; presence does not independently authenticate documents or the epistemic tier.
- `SourceOccurrenceV1` binds the exact byte span of an independently trusted original artifact to the SHA-256 root of the selected carrier bytes. The same carrier may have multiple distinct occurrence roots.
- `ContextualReadingV1` binds each candidate to context bytes, an existing MHP `SemanticLineageEnvelopeV1`, and an existing independently trusted `HeritageReceiptV1`. Multiple candidate readings of one occurrence are retained, including multiple readings in one context.
- `ContextBindingReceiptV1` must resolve from an **additional independent trusted store**. It binds the holon metadata root, source occurrence, reading ID, context root, MHP envelope, exact transform root, and derived payload. Without it, swapping a plausible context or holon still fails closed.
- `HolonMeaningVerifierV1` obtains original/context/derived bytes, source/derived ClaimSet, envelope and heritage receipts, plus trusted context-binding receipts **from trusted external stores**. It verifies content hashes, source span, envelope/receipt pairings, and exact MHP source/derived references. It issues `authority_class=NONE` evidence only; no effect or canonical admission.
- Roots use the repository's `canonical_hash` domain separation. Reading order is canonicalized by reading ID; no interpretation is picked as inherently correct.

## Distinctions that must not be collapsed

| Distinction | Rule |
| --- | --- |
| Glyph / occurrence | Byte-equal signs can come from different origin artifacts or spans; distinct occurrence roots |
| Occurrence / meaning | A carrier root does not pick one reading; all readings require context and proof-lineage refs |
| Holon tier / truth | `T0` / `T1` / `T2` and Drive IDs are metadata claims, not proof of correctness |
| MHP receipt / validity of interpreted proposition | A trusted receipt certifies authenticated transformation and declared loss, not empirical truth |
| Hash / actual trust | A correct 64-hex root without a trusted-store readback is insufficient |
| Local holon edges / global holarchy | Local self-edge checks do not prove graph closure or acyclicity of an external registry |
| Canonical ontology / context-dependent readings | Canonical terms remain unique; readings remain separate contextual hypotheses |

## Acceptance and falsifiers

The exact-head workflow runs the new native Python integration tests and three existing MHP suites. It checks two interpretations of `A` with distinct context and derived payloads; identical `A` in two original artifacts; reading-order canonicalization; missing/mismatched source span, artifact, context, context-binding attestation, holon metadata, envelope, receipt, claimset and derived bytes; self-edges, invalid spans, duplicate reading IDs, schema extension, and unbacked high-tier labels. Test-provided stores are deliberately finite fixtures, **not a claim of deployed trust infrastructure**.

## Whole-graph verifier V1: bounded closed-world holarchy

Added the strictly read-only `harness/sdk/holon_graph_verifier.py` with native falsifiers in `harness/tests/test_holon_graph_verifier.py`. It consumes the existing `HolonSnapshotV1`, `HolonMeaningLensV1`, and verified `HolonMeaningReceiptV1` from this bridge. It does **not** invent an alternative meaning/proof engine or modify `HolonMetadata` or the merged MHP kernels.

- **Bounded inventory:** `HolonGraphManifestV1` is a content-addressed enumeration of claimed nodes and their claimed meaning receipts. The verifier retrieves the manifest independently from a trusted store and retrieves every declared node by its exact `HolonSnapshotV1.root`. At most 4096 nodes, 32768 declared parent edges, 16384 meaning receipts and 16384 research document references are permitted. It checks only **closure relative to this supplied manifest**, not whether every holon in every AEGIS repository or Drive exists in that manifest.
- **Bidirectional topology:** each declared `part_of` must point to a listed parent with the reciprocal `composed_of`; each `composed_of` must point to a listed child with the reciprocal `part_of`. Missing targets or asymmetry fail closed. Multiple parents are explicitly permitted; the holarchy is a DAG, not necessarily a tree.
- **Acyclicity / scale direction:** deterministic, iterative Kahn traversal rejects cycles without recursive-stack exhaustion. A parent must not be at a *lower* HolonicScale than its child. Equal-scale parent/child relations are currently permitted; whether they should be forbidden requires a separate ontology-level policy.
- **Research provenance:** every referenced research-document identifier must resolve through a separate trusted source-attestation store to an exact nonempty byte artifact; digest mismatches fail closed. Each T0/T1/T2 holon requires at least one attested T0/T1/T2 research source. **Trust-store integrity, actual independent review and document semantics are environmental assumptions**, not inferred from a review hash or a string in `provenance`.
- **Contextual meaning:** for every **declared** meaning receipt, the verifier fetches an authenticated `HolonMeaningLensV1`, re-runs `HolonMeaningVerifierV1` against its MHP-1 and context-binding stores, and checks that the new receipt is byte-for-byte the trusted prior receipt. A holon edit cannot inherit a receipt tied to an older holon root.
- **No semantic collapse:** all context-dependent readings remain separate. The metric `competing_reading_count` counts additional alternative reading candidates, **not logical contradictions, proven non-equivalence or mutually exclusive propositions**. Incompatibility requires independently verified semantic premises and an explicit proof of incompatibility under a stated shared scope, which is **not established** by V1.
- **Epistemic/authority boundary:** `PASS_STRUCTURAL_ONLY` and `authority_class=NONE` certify an authenticated, internally coherent *declared* graph only. Neither mathematical validity, cultural intent, author identity, formal semantic soundness, deployed provenance infrastructure, full corpus completeness nor execution authority follows from a passing graph receipt.

The dedicated exact-head workflow includes the new graph falsifiers and the inherited MHP suites. The first graph-enabled commit `5a157b2afee01d6a086661d25aef24d6dbcba65a` passed **77/77 tests** in [Holon Meaning Bridge V1 run 43846595295](https://github.com/Aegis-Omega/AEGIS-OMEGA/actions/runs/43846595295). ## Indexed semantic contexts: finite compatibility without semantic overclaim

The operator's `Indexed Semantic Systems` research (private Google Drive document `194W-stG1ZY57dlw4dhwJJwGJsfpimIFpp6mkDQYLph0`) distinguishes context-indexed fibers, reindexing, and existence of compatible global selections; it **explicitly forbids inferring temporal evolution or semantic drift merely from the existence of reindexing**. Its categorical structures are **not** encoded or proved by the implementation below.

- `harness/sdk/holon_indexed_context.py` is a strictly **finite constraint-satisfaction analogue**: every context has a nonempty domain of specific reading IDs, and separately trusted `ContextRelationReceiptV1` instances declare allowed ordered pairs between two exact MHP-1 context roots. No lexical similarity or inferred equivalence may create a relation.
- The verifier retrieves the exact `HolonMeaningLensV1` and corresponding existing MHP-1 receipt from independent trusted stores and re-verifies them. It then retrieves every claimed relation by content-addressed receipt root. Absent, moved, duplicated, malformed, untrusted or disconnected context relations are denied, rather than treated as semantic facts.
- The pure solver first validates the complete relation index, then performs iterative arc-consistency pruning and deterministic bounded DFS (maximum 12 contexts, 12 readings per context, 80 relations, 144 declared pairs per relation). The default search budget is 32,768 explored nodes. `OPEN_FINITE_SEARCH_BUDGET` signals **unresolved** bounded computation, never a mathematical counterexample.
- `PASS_FINITE_COMPATIBILITY_ONLY` means that the selected reading tuple satisfies **exactly the supplied finite allowed-pair tables**, with `authority_class=NONE`. `NO_FINITE_ASSIGNMENT_RELATIVE_TO_ATTESTED_RELATIONS` says only that no assignment satisfies those particular tables. Neither outcome proves a Cartesian section, validity of transport, cultural intent, proposition truth, or consistency of the full ontology.
- **Counterexample to local-to-global promotion:** three contexts with binary readings and the pairwise inequality relation on all three edges admit individual pairs but no joint assignment (an odd-cycle two-coloring obstruction). This is a finite CSP counterexample, **not a disproof or theorem about the source's categorical global-section formulation**.
- **Algorithmic improvement:** a chain of 12 contexts each with 12 candidate readings has (12^{12}) naive combinations; equality constraints on its edges allow the revised solver to find a compatible witness by propagation and a small bounded search. The previous algorithm returned `OPEN` merely because the Cartesian product exceeded its threshold. This comparison is a deterministic constructed case, **not a measured production workload or a universal complexity guarantee**.
- **Independent falsification:** the regression suite includes 250 seeded small connected graphs, each cross-checked against a separate direct exhaustive enumerator. It also verifies true quota exhaustion, invalid graph/index evidence before quota handling, and deterministic root/assignment results.

**Exact-head verification checkpoint:** [Holon Meaning Bridge V1 run 43855826773](https://github.com/Aegis-Omega/AEGIS-OMEGA/actions/runs/43855826773) on `b9302c4b88e6975af704f44741ec4088b209e233`: **159/159 Python tests PASS** and **57/57 TypeScript/Python hash vectors PASS**. ## Positive context-relations backed by existing semantic morphisms

The finite indexed-context solver previously accepted an explicitly supplied `ContextRelationReceiptV1` as the complete *allowed pair table*, without establishing that each positive pair had independent proof support. The new read-only bridge `harness/sdk/holon_context_morphism_proof.py` connects that input to **existing AEGIS Antropolimorphic `MorphismKind.SEMANTIC`**, without inventing an alternative semantic prover.

- **Exact scope:** a `ContextRelationProofBundleV1` binds a prior MHP `HolonMeaningReceiptV1`, an existing context relation root, and one `ContextReadingMorphismWitnessV1` for every *allowed* ordered pair. Missing, extra, duplicated or transposed pairs fail closed. A zero-pair table does not mint an affirmative semantic-proof certificate.
- **Origin and context:** the verifier fetches and replays the actual MHP lens/meaning receipt, separately reads each `ContextBindingReceiptV1`, and constructs a domain-separated proof-convention root covering the holon root, original occurrence, MHP receipt, relation root, source/target contexts, reading IDs, and both exact context-binding roots. The direction of each pair is significant. Same carrier bytes in different contexts do not automatically count as equivalent.
- **No forged semantic proof:** for each allowed pair, the verifier independently retrieves a `MorphismReceiptV1` and its semantic `MorphismEnvelopeV1` and re-runs the **existing** `MorphismVerifierRegistryV1.verify_and_issue`. It requires exact directional derived-payload endpoints, exact context-derived proof convention and an equal reissued receipt, with no unvalidated predecessor/composition chain. The existing morphism engine in turn checks trusted, subject-bound semantic *soundness* and *correspondence* proof-artifact receipts.
- **Strict composition:** `ProofBoundIndexedContextVerifierV1` independently reruns the finite solver and all prior pair-evidence bundles. It accepts a positive finite solution only when **every relation in that exact problem** is covered by authenticated, replayed pair support and MHP scope. It has `authority_class=NONE`. Standalone CSP results remain structurally useful but are **not** silently upgraded into semantically supported results.
- **Critical epistemic limit:** a trusted *proof artifact receipt* means that the configured proof-artifact store accepted an exact subject under a policy. It does **not** establish that the external proof verifier is independently sound, or that a cultural/linguistic interpretation is a true description of intent. This bridge certifies conditional positive pair support, **not** the nonexistence of all unlisted pairs or any globally valid Cartesian section. It explicitly refuses to certify UNSAT from positive-pair evidence alone.
- **Threat model tested:** absent soundness/correspondence artifact, forged artifact, untrusted semantic morphism, missing MHP source, wrong proof convention, swapped direction, missing pair, nonsemantic morphism kind, borrowed meaning receipt and omitted relation proof all fail closed. The test stores are finite fixtures, not a claim of a deployed independent semantic proof service.

## Finite Boolean global model V1: genuine local-to-global obstruction

The executable `harness/sdk/holon_finite_semantics.py` proves complete pairwise compatibility tables by evaluating canonical, exact-byte, MHP-1-derived Boolean formulas. It accepts a bounded AST of variable, constant, NOT, AND, OR with at most 8 sorted ASCII-named variables and at most 256 valuations. Unknown operators, duplicate JSON keys, noncanonical payload bytes, malformed variable names and mismatched variable universes are rejected. The source occurrence and each contextual interpretation remain provenance-bound through the existing MHP verifier. A formal Boolean encoding's fidelity to a speaker's meaning **is not established**.

The new `harness/sdk/holon_finite_global_model.py` checks the **entire declared contextual graph** under a single variable universe. It replays the indexed-context verifier, MHP receipt, complete truth-table proof for every indexed pair, exact derived source bytes and authenticated context bindings before issuing any conclusion. Pairwise satisfaction does **not** imply one shared valuation:

- Example: contexts with formal readings `p`, `q`, `NOT(p AND q)` each have pairwise shared satisfying valuations. Yet no valuation satisfies all three simultaneously, and the global checker issues `PROVEN_NO_SHARED_FINITE_BOOLEAN_MODEL`, explicitly **relative to the exact formal encoding**.
- Contexts may carry **multiple distinct readings**. The verifier ORs each context's reading truth masks and then ANDs these masks across contexts to calculate all shared valuations. It stores canonical 64-digit hexadecimal bit masks per context, their global intersection, the number of shared valuations and the least satisfying valuation (if any). The resulting receipt remains `authority_class=NONE` and is bound by an independent domain-separated SHA-256 root.
- A nonempty global intersection proves existence of a shared valuation and yields a deterministic selection of one reading in each context. An empty intersection proves finite-model `UNSAT` after exhausting all at most 256 valuations. Both claims require each separately verified pair table to match the exact MHP-derived Boolean formulas.
- The code deliberately **does not** claim a category-theoretic global section, a universal semantic equivalence, an empirical truth, an unambiguous human intention, completeness of the AEGIS corpus or permission to execute a decision.

### Finite global receipt replay and evidence retention

`FiniteGlobalReceiptReplayVerifierV1` extends the existing verifier with independently retrieved `FiniteGlobalModelReceiptV1` readback. Before accepting a previously issued SAT or UNSAT receipt, it verifies the receipt's content-addressed root, then **re-runs the full original MHP, contextual relation, indexed graph and exact-byte Boolean model verification** against the currently trusted stores. The reissued result must be byte-for-byte equal to the stored receipt, including the context truth masks, total global valuation mask, exact witness and provenance roots.

- SAT and UNSAT replay are independently tested as stable under unchanged evidence.
- Removing the stored receipt, original heritage receipt, or a formerly verified relation denies admission. Altering the stored truth mask without a matching root also denies admission. Invalid roots cannot produce a false `OPEN` or `UNSAT`.
- This is an **evidence custody and repeatability check**, not an independent mathematical implementation of the truth-table algorithm. The separate exhaustive-oracle tests are what support the finite semantic calculation; replay merely guards against stale or missing evidence.
- All receipts remain `authority_class=NONE`, and no production trust-store adapter or external provenance service is asserted deployed.

## Independent finite certificate checking and dual evidence

The original finite-global verifier and its receipt replay use the **same producer implementation**. A shared logical bug could therefore pass both the initial run and replay. To test this causal weakness, the draft PR now contains an independent finite semantics verification path:

- `harness/sdk/holon_finite_certificate_checker.py` independently enumerates every allowed Boolean valuation and interprets the canonical AST using a separate evaluator. It **does not call** the producer's `finite_truth_mask`, global-model verification or formal pair-relation verifier. It independently recomputes every complete relation table, source-derived formula roots, per-context masks, shared mask, first witness and hash-bound proof.
- `harness/sdk/holon_finite_dual_evidence.py` requires both the **original producer receipt replay** and the **independent semantic certificate checker** to accept the **same content-addressed receipt** and exact verification root before issuing a separate evidence-only receipt. Either failure denies the dual-evidence result.
- Adversarial tests include a fully rehashed but semantically forged certificate and a deliberately corrupted producer that emits a false UNSAT result. Its *own replay still agrees with the false result*, while the independent checker rejects it. A separate fault injection makes the independent evaluator wrong and verifies that the dual gate refuses it as well.
- **Scope and assumptions:** this is independently implemented Boolean evaluation only. The parser, MHP provenance/receipt trust stores, SHA-256 canonicalization and exact source bytes remain shared dependencies. Neither check independently proves natural-language fidelity, completeness of the research corpus, an actual category-theoretic global section, production deployment, or authorization.
